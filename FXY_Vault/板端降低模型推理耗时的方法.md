
# 板端（嵌入式 / 边缘端，NPU/MCU/SoC，如瑞芯微、地平线、海思、Triton、Jetson）降低模型推理耗时的方法

整体思路分 4 大块：**模型结构优化 → 量化压缩 → 算子 / 图优化 → 部署 runtime & 硬件调度优化**，从上游训练到板端部署全链路。

> 目标：降低 latency（单帧耗时），同时尽量保住精度；部分手段会牺牲少量精度。

## 一、模型结构层面（训练 / 设计阶段，收益最大）

### 1. 轻量化网络结构设计

- 用轻量骨干：MobileNetV2/V3、ShuffleNet、MobileOne、RepVGG、ConvNeXt-Tiny，替换大 ResNet、ViT-L
- 降参策略：
    - 减少通道数（width multiplier）、降低输入分辨率（最直接！比如 640→480，计算量降为 \((480/640)^2=0.56\)）
    - 减少层数；减小注意力头数、embedding 维度（Transformer 模型）
- 算子替换：
    - 大卷积 `Conv3x3` → **深度可分离卷积 DWConv**
    - 普通 Conv → 重参数化卷积（RepVGG，训练多分支，推理合并成单路 3×3，减少分支开销）
    - 大 kernel 卷积用卷积分解；避免大的 dilation 空洞卷积（板端 NPU 往往低效）
- 砍掉冗余模块：删除多余分支、dropout、不必要的归一化层；尽量**减少分支、if 分支、动态 shape**（板端 NPU 对动态分支极不友好）

### 2. 模型剪枝 Pruning

- 非结构化剪枝：随机剪权重，硬件收益低，**板端一般不推荐**
- **结构化剪枝（通道剪枝）**：直接剪掉整个通道，减少 feature map 维度，能实实在在减少 MAC，NPU 可以直接提速；常用 L1 通道剪、Taylor 剪枝
- 注意：剪枝后一般需要 finetune 恢复精度

### 3. 知识蒸馏 Knowledge Distillation

用大教师模型软标签，训练小学生模型。

> 不是直接提速，是**用小模型达到接近大模型精度**，从而在同等精度下降低推理耗时。 适合：分类、检测、分割、Embedding 模型（你前面看的 CosineEmbeddingLoss 就可以做蒸馏）

## 二、量化（板端最常用，性价比极高）

把 FP32 浮点权重 / 激活转低精度，**减少带宽 + 硬件可以使用低精度算力单元**

1. **INT8 量化（最主流）**
    - PTQ：训练后量化，少量校准数据，不用重训；上手快
    - QAT：量化感知训练，训练时模拟量化噪声，精度损失更小，精度敏感任务首选
2. 更低精度：INT4 / UINT4；部分 NPU 支持 FP16/BF16
    - FP16：GPU/Jetson 常用；很多端侧 NPU 对 FP16 支持一般，不如 INT8 收益大

> ⚠️ 坑：
> 
> - 激活值范围波动大的层，量化误差爆炸；需要做层敏感分析，部分层保留 FP32
> - 部分算子（如 Softmax、LayerNorm、Tanh）在 INT8 上性能差，常保留浮点
> - 量化不是无脑降精度，要评估精度掉点

## 三、计算图优化（模型转换阶段，ONNX → 板端模型）

在模型转换工具（onnxsim、onnxoptimizer、NPU 工具链）做图融合：

1. **算子融合（fusion）** Conv + BN → 合并成单个 Conv；Conv+BN+ReLU 合并；Matmul+Add 融合；LayerNorm 融合。 原理：减少内存读写（访存是板端瓶颈！很多时候不是算力不够，是 DDR 带宽不够），减少算子调用开销。
2. 消除冗余算子：删除 Identity、Dropout、无用 Reshape、Slice、Squeeze/Unsqueeze 冗余节点
3. 常量折叠：预计算常量张量，推理时不再计算
4. 算子替换：把 NPU 不支持、低效算子替换为等价高效算子；避免复杂自定义算子（Custom Op，大概率落到 CPU，巨慢）
5. 固定输入 shape：**尽量不要动态输入尺寸**，动态 shape 会让 NPU 无法做图编译优化，latency 暴涨

> 核心：边缘板端 90% 场景瓶颈是**内存带宽，不是算力**。减少访存 > 单纯减少 MAC。

## 四、Runtime / 板端部署 & 调度优化（部署后调优）

### 1. 推理引擎选型

- 地平线：Horizon BPU（HBModel）
- 瑞芯微 RKNN、海思 NNIE、Jetson TensorRT、TFLite、ONNX Runtime、MNN、Tengine

> 一定要用硬件厂商原生工具链，通用 runtime 很难榨干 NPU 性能

### 2. 预处理后处理优化（非常容易被忽略）

很多项目预处理在 CPU 做，耗时占比很高：

- 把 resize、normalize、transpose、颜色空间转换（BGR↔RGB）**放到 NPU 做**（算子融合进模型图）
- 使用硬件 ISP 做图像缩放 / 色域转换，替代 CPU opencv
- 减少内存拷贝：避免 CPU↔NPU 之间反复拷贝 tensor，使用 DMA / 共享内存

### 3. 多线程、任务调度、内存策略

- 合理设置 NPU 核心数、推理线程数；不要超线程抢资源
- 内存预分配：提前申请 tensor buffer，推理时复用，避免每次推理 malloc/free（嵌入式 malloc 很慢）
- 批处理 Batch：
    - 离线 / 后台任务：增大 batch，提升吞吐
    - **低延迟实时任务（单帧）：batch=1**，大 batch 反而增加单帧 latency

> latency（单帧耗时） ≠ throughput（每秒帧数），板端实时场景优先看 latency

### 4. 算子硬件分配（异构调度）

NPU 跑 Conv/Matmul；复杂小算子不要丢 NPU，也不要全部丢 CPU：

- 大计算量算子放 NPU；少量复杂小算子放少量 CPU 核心
- 避免频繁 NPU-CPU 之间来回切换（数据迁移开销巨大）

## 五、进阶高级手段

1. **算子内核调优**：针对目标 NPU，手工选择最优 kernel、分块策略（部分厂商支持自定义 kernel）
2. **模型并行 / 流水线并行**：多 NPU 核流水线，适合大模型；小模型基本没用，反而增加开销
3. **缓存策略**：重复输入场景做 feature cache；视频流利用帧间冗余（如光流、特征缓存，视频检测常用）
4. 算子重写：把低效自定义算子，拆成硬件原生支持的基础算子组合

# 优先级排序（落地推荐顺序）

1. 降低输入分辨率 ✅（最简单，收益最大）
2. 图优化 + 算子融合，消除冗余节点 ✅
3. INT8 量化（PTQ 优先，精度掉点再上 QAT）✅
4. 结构化通道剪枝 + 蒸馏，设计更小模型 ✅
5. 预处理 / 后处理迁移到硬件、消除 CPU-NPU 内存拷贝 ✅
6. 内核 / 调度精细调优

# 常见踩坑提醒

1. MAC（乘加次数）下降 ≠ 板端 latency 同比下降：**访存瓶颈**，有些算子 MAC 低但访存大，速度提升有限
2. 不要盲目 INT4：部分 NPU INT4 算力提升有限，精度损失大，得不偿失
3. 动态 shape、大量分支、复杂自定义算子，是板端性能杀手
4. 评估时：**单独测模型推理耗时，不要把预处理、文件 IO、后处理一起算进去**，定位瓶颈
